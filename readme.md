# Warehouse Tracker

[![CI](https://github.com/SephirothGit/warehouse-tracker/actions/workflows/ci.yml/badge.svg)](https://github.com/SephirothGit/warehouse-tracker/actions/workflows/ci.yml)

REST API for warehouse inventory management, written in Go. Tracks stock across a warehouse → zone → rack → shelf hierarchy, with JWT authentication (refresh token rotation and reuse detection) and role-based access control.

## Stack

Go · PostgreSQL (`database/sql`, `lib/pq`) · chi v5 · `golang-jwt/jwt/v5` · bcrypt · `log/slog` · golang-migrate · cleanenv · testify + mockery · Docker · GitHub Actions

## Architecture

```
cmd/server/        entry point, wiring, graceful shutdown
internal/
  config/          YAML + env config, *_FILE secrets
  auth/            JWT, refresh tokens, password hashing, auth middleware
  repository/      SQL access, typed errors
  service/         business logic, validation
  handler/         HTTP handlers, RBAC / logging / timeout / rate limit / security headers
  worker/          expired refresh token cleanup
  mocks/           generated by mockery
migrations/        versioned SQL migrations
```

Layers depend on interfaces (`handler → service → repository`), so the service layer is tested with generated mocks and no database.

## Authentication

- **Access token:** JWT (HS256), 15 min TTL. Algorithm is pinned and expiry is required on validation.
- **Refresh token:** 32 random bytes (`crypto/rand`), 30 day TTL, only the SHA-256 hash is stored.
- **Rotation:** every `/refresh` revokes the used token and issues a new pair.
- **Reuse detection:** presenting a revoked refresh token revokes all tokens of that user.
- **Passwords:** bcrypt, 8–72 chars. Login returns the same error for unknown email and wrong password, with timing equalized.

## Authorization

Hierarchical RBAC: `warehouse_worker` < `manager` < `admin`.

| Operation | Minimum role |
|---|---|
| Read warehouses, zones, racks, shelves, products, stock | any authenticated user |
| Move / receive stock | any authenticated user |
| Create warehouses, zones, racks, shelves, products | `manager` |

New users are registered as `warehouse_worker`. The acting user in the stock audit log comes from the verified JWT, never from the request body.

## Data integrity

- Stock moves and receipts run in a transaction together with their audit record.
- Upserts via `INSERT ... ON CONFLICT DO UPDATE`; `quantity >= 0`
- Duplicate email / SKU → `409 Conflict` through typed errors.
- Foreign keys are indexed; timestamps are `TIMESTAMPTZ`.

## Operations

- `context.Context` from request to SQL driver; global request timeout.
- Bounded connection pool, `ReadHeaderTimeout`, graceful shutdown (`SIGINT`/`SIGTERM`).
- Structured JSON logs with request ID.
- Per-IP rate limiting on `/register`, `/login`, `/refresh`.
- Security headers on all responses.
- Paginated lists (`limit` 1–100, `offset`).
- `GET /healthz` pings the database.

## Run

### Docker

```bash
mkdir -p secrets
openssl rand -base64 32 > secrets/db_password.txt
openssl rand -base64 48 > secrets/jwt_secret.txt
docker compose up --build -d
```

Starts PostgreSQL, applies migrations, then starts the API on `:8080`.

### Without Docker

```bash
migrate -path migrations -database "$DATABASE_URL" up
go run ./cmd/server
```

## Configuration

`config.yaml` provides defaults; environment variables override them. Secrets can be passed as files via `DB_PASSWORD_FILE` and `JWT_SECRET_FILE`. See `.env.example` for the full list.

## Test

```bash
go test ./...
```

Covers token hashing, JWT validation (expired, wrong secret, wrong algorithm, missing expiry, `alg: none`) and the auth service against generated mocks.

## API

Protected routes need `Authorization: Bearer <access_token>`.

| Method | Path | Auth |
|---|---|---|
| POST | `/register`, `/login`, `/refresh`, `/logout` | public |
| GET | `/healthz` | public |
| GET | `/warehouses`, `/products` | any role |
| GET | `/zones?warehouse_id=`, `/racks?zone_id=`, `/shelves?rack_id=` | any role |
| GET | `/stock?shelf_id=` | any role |
| POST | `/stock/move`, `/stock/add` | any role |
| POST | `/warehouses`, `/zones`, `/racks`, `/shelves`, `/products` | `manager`+ |
