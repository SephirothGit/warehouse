# Warehouse Tracker

REST API for warehouse inventory management, written in Go. Tracks stock across a warehouse → zone → rack → shelf hierarchy, with JWT authentication (refresh token rotation, reuse detection) and role-based access control.

## Stack

Go · PostgreSQL (`database/sql`, `lib/pq`) · chi · `golang-jwt/jwt/v5` · bcrypt · `log/slog` · testify + mockery

## Architecture

```
cmd/server/        entry point, wiring, graceful shutdown
internal/
  auth/            JWT, refresh tokens, password hashing, auth middleware
  repository/      SQL access, typed errors
  service/         business logic
  handler/         HTTP handlers, RBAC / logging / timeout middleware
  mocks/           generated by mockery
```

## Authentication

- **Access token:** JWT (HS256), 15 min TTL, stateless. The signing algorithm is pinned on validation to prevent `alg: none` and algorithm-confusion attacks.
- **Refresh token:** 32 random bytes from `crypto/rand`, 30 day TTL. Only its SHA-256 hash is stored.
- **Rotation:** every `/refresh` revokes the used token and issues a new pair.
- **Reuse detection:** presenting an already-revoked refresh token revokes all of that user's tokens.
- **Passwords:** bcrypt. Login returns the same error for an unknown email and a wrong password, which prevents user enumeration.

## Authorization

Hierarchical RBAC: `warehouse_worker` < `manager` < `admin`. A role satisfies any requirement at or below its level.

| Operation | Minimum role |
|---|---|
| Read warehouses, zones, racks, shelves, products, stock | any authenticated user |
| Move / receive stock | any authenticated user |
| Create warehouses, zones, racks, shelves, products | `manager` |

New users are registered as `warehouse_worker`

## Data integrity

- `MoveStock` and `AddStock` run in a transaction: stock changes and the audit record commit together or not at all.
- Stock upserts use `INSERT ... ON CONFLICT DO UPDATE` on `(shelf_id, product_id)`.

## Operational concerns

- `context.Context` is propagated from the HTTP request through every layer to the SQL driver; a global request timeout middleware bounds all calls.
- Connection pool is bounded (`SetMaxOpenConns`, `SetMaxIdleConns`, `SetConnMaxLifetime`).
- Graceful shutdown on `SIGINT`/`SIGTERM` with a 15 s drain.
- Structured JSON logs (`slog`) with a per-request ID and duration.
- `GET /healthz` pings the database with its own short timeout (returns 503 on failure).

## Run

```bash
psql -U postgres -d warehouse_db -f schema.sql
```

`.env`:
```
DATABASE_URL=postgres://user:password@localhost:5432/warehouse_db?sslmode=disable
JWT_SECRET=<long random string>
```

```bash
go run ./cmd/server
```

Listens on `:8080`.

## Test

```bash
go test ./...
```

Covers token hashing, JWT generation/validation (expired, wrong secret, `alg: none`) and the auth service against generated repository mocks. To regenerate mocks after changing a repository interface: `mockery`.

## API

Protected routes need `Authorization: Bearer <access_token>`.

| Method | Path | Auth |
|---|---|---|
| POST | `/register`, `/login`, `/refresh`, `/logout` | public |
| GET | `/healthz` | public |
| GET | `/warehouses`, `/products` | any role |
| GET | `/zones?warehouse_id=`, `/racks?zone_id=`, `/shelves?rack_id=` | any role |
| GET | `/stock?shelf_id=` | any role |
| POST | `/stock/move`, `/stock/add` | any role |
| POST | `/warehouses`, `/zones`, `/racks`, `/shelves`, `/products` | `manager`+ |
